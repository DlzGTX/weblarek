# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Данные
#### Интерфейс IProduct
Нужен для описания товара

Поля интерфейса:

id: string - Id товара
title: string - название товара
image: string - изображение товара
category: string - категория товара
price: number | null - цена товара
description: string - описание товара в открывающимся окне

#### Интерфейс IBuyer
Нужен для описания данных покупателя при оформлении заказа

Поля интерфейса:

payment: TPayment  - тип оплаты
address: string - адрес покупателя
email: string - почтовый адрес покупателя
phone: string - номер покупателя

#### Тип TPayment
Нужен для описания типа оплаты заказа

Поля интерфейса:

TPayment = 'card' | 'cash' - Тип ограничивает оплату двумя значениями, чтобы нельзя было записать произвольную строку.

#### Тип IProductsResponse

Содержит ответ сервера на запрос товаров.

total: number;
items: IProduct[];

#### Тип IOrderRequest

Содержит тело заказа, отправляемое на сервер.

total: number;
items: string[];

#### Тип IOrderResponse

Содержит ответ сервера на заказ.

id: string;
total: number;

### Модели данных

#### Класс ProductModel
Хранит в себе информацию о том, какие товары отображаются в каталоге и о том, какой товар выбран для просмотра.

Поля класса:
items: IProduct[] - хранит массив всех товаров
preview: IProduct | null - хранит выбранный товар для отображения в превью

Методы класса:
setItems(items: IProduct[]): void - сохранение полученного массива товаров.

getItems(): IProduct[] - получение массива товаров.

getItem(id: string): IProduct | null - получение товара по id.

setPreview(item: IProduct): void - сохранение товара для просмотра в режиме превью.

getPreview(): IProduct | null - получение товара для просмотра в режиме превью.

#### Класс BasketModel
хранение товаров в корзине, которые пользователь выбрал для покупки

Поля класса:
items: IProduct[] - хранит массив товаров, выбранных покупателем для покупки.

Методы класса:
getItems(): IProduct[] - получение массива товаров, которые находятся в корзине.

addItem(product: IProduct): void - добавление товара в массив корзины.

removeItem(product: IProduct): void - удаление товара из массива корзины.

clear(): void - очистка корзины.

getTotal(): number - получение стоимости всех товаров в корзине.

getCount(): number - получение количества товаров в корзине.

hasItem(id: string): boolean - проверка наличия товара в корзине по его id.

#### Класс BuyerModel
данные покупателя указанные при оформлении заказа

Поля класса:
payment: TPayment  - вид оплаты.
address: string - адреc.
phone: string - телефон.
email: string - email.

Методы класса:
saveData(data: Partial<IBuyer>): void - Один общий метод сохранения данных в модели. Важно учесть, что должна быть реализована возможность сохранить только одно значение, например, только адрес или только телефон, не удалив при этом значения других полей, которые уже могут храниться в классе.

getData(): IBuyer - получение всех данных покупателя.

clearData(): void - очистка данных покупателя.

validate(): Partial<Record<keyof IBuyer, string>> - валидация данных. Метод валидации должен давать возможность определить не только валидность каждого отдельного поля, но и предоставлять информацию об ошибке, связанной с проверкой конкретного значения.

### Слой коммуникации
#### Класс ApiSрop
Методы класса:

getProducts() Promise<IProductsResponse> - делает get запрос на эндпоинт /product/ и возвращает объект, полученный от сервера, в котором находится массив товаров.

postOrder (order: IOrderRequest): Promise<IOrderResponse> - делает post запрос на эндпоинт /order/ и передаёт в него данные, полученные в параметрах метода, а возвращает объект, подтверждающий покупку на определенную сумму.

## Слой представления (View)

Классы View только показывают данные на странице и сообщают о действиях пользователя. Сами они ничего не хранят и не принимают решений. Нужные элементы разметки класс находит один раз в конструкторе, там же вешает слушатели. Данные в компонент передаются через `render`, который вызывает сеттеры.

### Header
Шапка сайта: кнопка корзины и счётчик.
 Конструктор: `events`, `container`.
 Поля: `basketButton` (кнопка корзины), `counterElement` (счётчик).
 `set counter(value: number)` - показывает число в счётчике.
 Событие: клик по корзине -> `basket:open`.

### Modal
Модальное окно. Окно не знает что показывать, это ему передают.
 Конструктор: `events`, `container`.
 Поля: `closeButton`, `contentElement` (место для содержимого), `windowElement` (само окно), `_pageWrapper` (обёртка страницы, нужна для блокировки прокрутки).
 `set content(value: HTMLElement)` - кладёт элемент в окно.
 `open()` - показывает окно и блокирует прокрутку страницы.
 `close()` - прячет окно, возвращает прокрутку и очищает содержимое.

### Card
Общий родитель трёх карточек. Умеет показывать название и цену.
 Конструктор: `container`.
 Поля: `titleElement`, `priceElement`.
 `set title(value: string)` - показывает название.
 `set price(value: number | null)` - показывает «N синапсов», а если цены нет, пишет «Бесценно».
 Интерфейс `ICardAction` описывает обработчик клика `onClick`, который карточка получает в конструкторе.

### CardCatalog
Карточка в каталоге. Наследуется от `Card`.
 Конструктор: `container`, необязательный `actions`.
 Поля: `categoryElement`, `imageElement`.
 `set category(value: string)` - показывает категорию и подставляет её цвет из `categoryMap`.
 `set image(value: string)` - ставит картинку (к имени файла добавляется `CDN_URL`).
 Клик по карточке вызывает `onClick`.

### CardPreview
Подробная карточка в модальном окне. Наследуется от `Card`.
 Конструктор: `container`, необязательный `actions`.
 Поля: `categoryElement`, `imageElement`, `descriptionElement`, `buttonElement`.
 `category` и `image` работают как в `CardCatalog`.
 `set description(value: string)` - показывает описание.
 `set buttonText(value: string)` - задаёт текст кнопки.
 `set buttonDisabled(value: boolean)` - блокирует или включает кнопку.
 Какой текст на кнопке и заблокирована ли она, карточка не решает, это присылает презентер. Клик по кнопке вызывает `onClick`.

### CardBasket
Строка товара в корзине. Наследуется от `Card`.
 Конструктор: `container`, необязательный `actions`.
 Поля: `indexElement` (номер), `deleteButton` (кнопка удаления).
 `set index(value: number)` - показывает номер позиции.
 Клик по кнопке удаления вызывает `onClick`.

### Basket
Корзина: список, итоговая сумма и кнопка «Оформить».
 Конструктор: `events`, `container`.
 Поля: `listElement`, `buttonElement`, `priceElement`.
 `set items(value: HTMLElement[])` - показывает карточки. Если список пуст, пишет «Корзина пуста» и блокирует кнопку.
 `set total(value: number)` - показывает сумму в формате «N синапсов».
 Событие: клик по «Оформить» -> `order:open`.

### Form
Общий родитель двух форм заказа.
 Конструктор: `events`, `container` (форма).
 Поля: `submitButton`, `errorsElement`.
 `set valid(value: boolean)` - блокирует кнопку, если форма заполнена неверно.
 `set errors(value: string)` - показывает текст ошибок.
 События (имя формы берётся из её атрибута `name`): ввод в поле -> `имя.поле:change` с данными `{ field, value }`; отправка -> `имя:submit`.

### OrderForm
Первая форма: способ оплаты и адрес. Наследуется от `Form`.
 Поля: `cardButton`, `cashButton`, `addressInput`.
 `set payment(value: TPayment)` - подсвечивает выбранный способ оплаты.
 `set address(value: string)` - записывает адрес в поле.
 Событие: клик по способу оплаты -> `order.payment:change`.

### ContactsForm
Вторая форма: email и телефон. Наследуется от `Form`.
 Поля: `emailElement`, `phoneElement`.
 `set email(value: string)` и `set phone(value: string)` - записывают значения в поля.

### Gallery
Каталог на главной странице.
 Конструктор: `container`.
 `set catalog(items: HTMLElement[])` - заменяет содержимое галереи на переданные карточки.

### Success
Окно «Заказ оформлен».
 Конструктор: `events`, `container`.
 Поля: `descriptionElement`, `closeButton`.
 `set total(value: number)` - показывает «Списано N синапсов».
 Событие: клик по кнопке -> `success:close`.

## Презентер

Презентер находится в `src/main.ts`, отдельного класса нет. Он создаёт модели, представления и `ApiShop`, а затем подписывается на события. Данные меняются только через методы моделей. Представления перерисовываются только после событий моделей или при открытии модального окна. Сам презентер события не создаёт, кроме обработчиков `onClick` для карточек.

Вспомогательные функции:
 `getBasketData()` - собирает карточки корзины и считает сумму;
  `renderOrderForm()` и `renderContactsForm()` - берут данные покупателя, проверяют их и передают форме вместе с ошибками.
